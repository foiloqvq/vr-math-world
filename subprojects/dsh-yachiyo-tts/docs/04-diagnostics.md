# 量化诊断方法论

思路：**把主观听感翻译成可测的数字，先测再改，改完再测。** 工具在 `tools/`。

## 指标与适用场景

| 指标 | 怎么算 | 能发现什么 | 局限 |
| --- | --- | --- | --- |
| 中位基频 f0（自相关） | 40ms 窗 / 20ms 步，取 70~400Hz 自相关峰，要求清晰度 > 0.3 | 分块之间的**音高台阶**（"念到一半高低"） | 句子本身的语调起伏会被误当漂移 |
| 停顿底噪 | 每 10ms RMS，取最低 10% 帧的均值 | 参考素材有没有 BGM/房间噪声；输出有没有嘶声底 | **测不出"混在语音里"的沙声** |
| 采样点突变数 | `abs(diff(x)) > 0.25` 的计数 | 咔哒声/断口 | **会被"声音更亮"影响，不是纯噪声指标** |
| 6kHz 以上能量 | `highpass=f=6000, volumedetect` | 亮度/齿音/空气感 | 与伪影同频段，无法区分 |
| 内部停顿数 | 静音段 20~400ms 且前后有语音 | 句中莫名停顿（"断断续续"） | 与正常换气难区分 |

## 我踩过的坑（两次被自己的指标骗）

1. **把"噪声低"当成"质量好"**：我一开始用"突变点"筛参考音频，挑出了 4/3 的候选，
   结果**听感更吵**——因为那个指标测的是亮度，不是噪声；真正的问题是那些素材**语音底下有 BGM**，
   而我的底噪测量是**全局**的（被 24 分钟里的真静音稀释了）。改成"只统计语音段内的停顿"才看见 -39 dB。
2. **测错了位置**：我量输出的"停顿底噪"得到 -94 dB（等于数字静音），据此判断"没有底噪问题"——
   但用户听到的沙声是**混在语音内部**的，静音区当然测不到。

**结论：任何代理指标都要先跟听感对齐一次，再拿它做决策。** 本次最终以真机试听为准。

## 快速用法

```bash
python tools/measure_pitch.py --dir <分块wav目录>          # 音高台阶
python tools/measure_audio.py --file a.wav --file b.wav    # 响度/底噪/毛刺
python tools/build_ab.py --src raw.wav --preset loudness   # 生成 A/B 变体
```
